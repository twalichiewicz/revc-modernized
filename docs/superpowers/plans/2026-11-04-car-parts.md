# Car Parts Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Visible native damage/swinging stages before doors, hoods, trunks and bumpers detach on heavier subsequent hits.

**Architecture:** Pure per-component force/episode rules in `partsmodel`; a scoped native hook owner in `carparts`. Existing control/damage/repair chains plus one new ApplyDamage hook.

**Tech Stack:** C++17 plugin, Makefile fixtures, isolated exact-build arm64 leaf regression.

**Spec:** `docs/superpowers/specs/2026-11-04-car-parts-design.md`.

## Global Constraints

macVC 1.0.5217 only. CarParts switch, eight native parts only, native health/protections/repair ownership, bounded 256-slot history, no per-frame allocation. State factors 1.00/0.85/0.55; quiet contact gap 350 ms.

## Review Focus

1. Sustained contact across frames must not run one part through all stages; a later harder hit can detach it.
2. Native protected doors can reject a swinging state; log/history use the final native state.
3. Scripted/unscoped calls, other vehicle classes and unrelated damage groups are exact pass-throughs.
4. Repair, backward clocks and recycled pool/clump identities cannot carry old contact episodes.
5. Nested controllers/damage callbacks preserve the correct actor, native health and handling/transmission allocation.
