# Car Glass Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Side and rear windows shatter independently from bullets and crashes, alongside the native windscreen.

**Architecture:** Pure pane classification plus a native geometry owner; certified bullet contacts feed the owner, native damage/repair/deletion hooks maintain lifecycle. Rendered geometry is also what rain and precision bullets query.

**Tech Stack:** C++17, macVC 1.0.5217, Makefile fixtures and installed assets.

**Spec:** `docs/superpowers/specs/2026-11-04-car-glass-design.md`.

## Global Constraints

Cars only, bounded memory, no shared geometry/material writes, native damage and proof ownership, CarGlass disabled is a pass-through. Existing handling values are unchanged.

## Review Focus

1. Two cars sharing geometry: breaking one window leaves its sibling and opaque door faces intact.
2. Read-only traces, wall-blocked shots and recycled pool slots produce no glass effects.
3. Repair, clump deletion and allocation failure release references and preserve a valid native clump.
4. Native front windscreen crack/shatter remains single-owned; hidden/missing components never reappear.
5. Real car geometry (damaged variants, quarter windows and transparent lamps) is classified conservatively.

## Wall-impact crash correction (2026-11-04)

The first live run crashed at 02:55:21 after a wall impact. The report reaches
`carglass::Door -> Break -> Copy -> RpGeometryUnlock -> Geometry::buildTristrips`.
The native cold path prints `TRISTRIP verify failed` and exits. This supersedes
the earlier offline-only readiness claim for that build.

**Cause:** private copies retained the source geometry's TRISTRIP bit while
collapsing broken window triangles. The strip verifier skips repeated-index
triangles, then requires every original triangle to have been seen. The old
owner fixture used flags 0x3e (no strip bit) and stubbed Unlock, so it could not
exercise this failure.

**Fix:** clear only TRISTRIP (bit 0) when creating a private copy. The native list
builder accepts the zero-area glass faces while preserving triangle ordinals,
opaque faces, materials, UV sets and other flags. Shared originals and repairs
retain their original geometry and topology.

**Real renderer regression:** `tests/test_carglass_rw.cpp` calls the production
Copy function and librw's real Geometry::unlock/buildMeshes, using the NULL
backend. Before the fix the mixed-body stripped input exited 1 with the exact
`TRISTRIP verify failed` message; after the fix all eight strip/list ×
intact/broken × mixed/glass-only cases pass, with all native geometry/material
references released. The normal owner fixture now starts with strip geometry
and checks both list copies and untouched strip originals.

The native 1.0.5217 buildMeshes disassembly independently confirms bit 0 at
Geometry+0x10 branches to buildTristrips. The separate open-source renderer used
for the executable regression was [librw 18532c2](https://github.com/aap/librw/tree/18532c2e13efbc1aa43f0b00b4459831f9414de0),
with the same verifier condition. This test runs no game process or save logic.

To rerun with an explicitly supplied NULL-backend librw build:

```sh
cmake -S /path/to/librw -B /path/to/librw-build \
  -DLIBRW_PLATFORM=NULL -DLIBRW_TOOLS=OFF -DLIBRW_INSTALL=OFF \
  -DCMAKE_BUILD_TYPE=Debug -DCMAKE_OSX_DEPLOYMENT_TARGET=15.0
cmake --build /path/to/librw-build -j4
make test-carglass-rw LIBRW_ROOT=/path/to/librw \
  LIBRW_STATIC=/path/to/librw-build/src/librw.a
```

The optional target fetches no dependencies and is separate from the ordinary
unit/asset suites. The remaining live acceptance is the original wall-impact
scenario and the rendered glass/shard/repair presentation.

Final crash-fix verification: `make -j4 all test test-game-assets` exited 0,
without compiler warnings or failures. The owner fixture and all eight real
mesh-builder cases also pass under address/undefined sanitizers. Targeted
independent review found no actionable issues; its explicit limit is live GPU
rendering/gameplay. `install.sh` exited 0 with the game closed; installed plugin
bytes match the new build, and executable signing verifies with the installer's
existing resource-check scope. A fresh in-game wall-impact check remains pending.
