## Decisions and practical limits

- Work stayed in the existing dirty checkout on a new branch, with an initial-file snapshot, so none
  of the previous uncommitted work was omitted. The whole combined working tree remains uncommitted.
- Independent module owners worked in parallel; root integrated build, configuration, hooks and
  player lifecycle. No additional user approvals were requested for routine implementation decisions.
- APB history is retained, while a wholly clean description prevents recognition under the APB.
  Returning to recorded clothes/vehicle can expose the player again.
- New default building heights are accurate relative heights; existing INI values were not migrated
  or overwritten. Users with the old 0.6 value retain it until changed explicitly.
- Race arrows are limited to verified sequential race script layouts. Unsupported or unordered
  checkpoints are left unchanged rather than inferred from unrelated blips.
- NPC reactions use a custom constrained articulated simulation, not proprietary middleware. The
  active set is capped at 12, fixed-step catch-up at four steps, native contact queries at 192 per
  sweep. These bounds prevent unbounded work; they do not establish an acceptable real frame budget.
- Mission, cutscene, attached and vehicle-seated NPCs retain their controllers. Saturation or missing
  APIs falls back to native behavior. Timeline changes discard old-world records before lookup.
- No code-only test establishes visual/gameplay acceptance. Do not close issues or mark the backlog
  complete until the remaining scenarios above pass.
