# Engine source availability and a reproducible host candidate

2026-11-05. Research only: public repository/API reads, source inspection, archive listing and hashes. No engine was compiled, installed or executed for this note. No maintainer was contacted, no credentials were requested, and no external repository was changed.

**Decision: no public documented path to matching macVC 1.0.5217 engine source was found. A usable, separately identified source host is available: `mrxenginner/reVC`, `miami`, pinned to `a26fff4af555a8a425ac9f17d1dd718d00d1f942`, with its readable `mrxenginner/librw` submodule pinned to `0ad67ee226ea51beb3f465cb8857195e4db16029`.** Prefer that relatively small OpenGL host for the first native query-geometry proof. It is a different host; source availability does not establish macVC ABI, renderer, plugin or save compatibility, and this research does not establish a successful build.

This follows the [aircraft/building host-contract audit](2026-11-05-aircraft-building-contracts.md). That audit rejected the current binary adapter's per-instance geometry authority. Finding source enables a bridge; it does not accept the bridge or the experimental solver.

Subsequent implementation: the [source-host build/query proof](2026-11-05-source-host-query-proof.md) now records actual builds and executable tests. The research recipe below remains labelled unexecuted as research evidence; measured build results belong to that follow-up.

## Source-host candidates

### Preferred: mrxenginner/reVC miami, a separate native OpenGL host

Pinned engine: [`a26fff4af555a8a425ac9f17d1dd718d00d1f942`](https://github.com/mrxenginner/reVC/tree/a26fff4af555a8a425ac9f17d1dd718d00d1f942). The complete [source tree](https://api.github.com/repos/mrxenginner/reVC/git/trees/a26fff4af555a8a425ac9f17d1dd718d00d1f942?recursive=1) contains `src/core/World.cpp`, `src/entities/{Entity,Physical}.cpp`, `src/collision/Collision.cpp`, `src/vehicles/Plane.cpp`, streaming, model information and rendering code. The root build explicitly sets executable `reVC` and project `REVC`. This is engine source, not a plugin or an installer-only repository. [CMake root](https://github.com/mrxenginner/reVC/blob/a26fff4af555a8a425ac9f17d1dd718d00d1f942/CMakeLists.txt).

Native macOS support is present in the actual pinned build files: ARM64 and AMD64 Premake targets, `arm64-apple-macos11`, Apple Silicon Homebrew paths, architecture-aware CMake deployment targets, app-bundle generation, dependency embedding and signing. The merged [macOS support PR #42](https://github.com/mrxenginner/reVC/pull/42) describes these additions; its merge `a03a68de95e4c0dd28dba3e1a9b1993de9396591` is in the inspected history. [Pinned Premake](https://github.com/mrxenginner/reVC/blob/a26fff4af555a8a425ac9f17d1dd718d00d1f942/premake5.lua), [executable CMake](https://github.com/mrxenginner/reVC/blob/a26fff4af555a8a425ac9f17d1dd718d00d1f942/src/CMakeLists.txt).

The engine pins `vendor/librw` to `0ad67ee226ea51beb3f465cb8857195e4db16029`, and [`.gitmodules`](https://github.com/mrxenginner/reVC/blob/a26fff4af555a8a425ac9f17d1dd718d00d1f942/.gitmodules) points it to `mrxenginner/librw`. Both the exact [library commit](https://github.com/mrxenginner/librw/commit/0ad67ee226ea51beb3f465cb8857195e4db16029) and [CMake source](https://github.com/mrxenginner/librw/blob/0ad67ee226ea51beb3f465cb8857195e4db16029/CMakeLists.txt) were readable. Selecting only this required submodule avoids acquiring optional Ogg/Opus submodules when those features are off.

Required dependency acquisition is documented by the build files: CMake, a C/C++ toolchain with macOS SDK, GLFW, OpenAL Soft and mpg123; pthread and OpenGL come through system/toolchain discovery. Optional libsndfile and Opus are off by default. GLFW's [library build file](https://github.com/mrxenginner/librw/blob/0ad67ee226ea51beb3f465cb8857195e4db16029/src/CMakeLists.txt) uses `find_package(glfw3)` and OpenGL discovery. The first-party [macOS build wiki](https://github.com/mrxenginner/reVC/wiki/Building-on-MacOS) names ARM64 configurations and GLFW >=3.3/OpenAL/mpg123, but still contains old re3/GTA III paths. Use the pinned reVC build files to resolve those stale instructions.

An explicit candidate recipe, derived from those files, is below. **It was not executed in this research.** A successful reproducible-host deliverable must retain its actual configure/build logs, toolchain/dependency versions, source/submodule hashes, any required patch and executable hash.

```sh
# Run in a separate research checkout; do not replace the installed macVC app.
brew install cmake glfw openal-soft mpg123
git clone --no-checkout https://github.com/mrxenginner/reVC.git reVC-source-host
git -C reVC-source-host checkout --detach a26fff4af555a8a425ac9f17d1dd718d00d1f942
git -C reVC-source-host submodule update --init vendor/librw
git -C reVC-source-host/vendor/librw rev-parse HEAD
# Expected: 0ad67ee226ea51beb3f465cb8857195e4db16029

cmake -S reVC-source-host -B reVC-source-host/build-host \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DCMAKE_OSX_ARCHITECTURES=arm64 \
  -DCMAKE_OSX_DEPLOYMENT_TARGET=11.0 \
  -DCMAKE_PREFIX_PATH="/opt/homebrew;/opt/homebrew/opt/openal-soft" \
  -DLIBRW_PLATFORM=GL3 -DLIBRW_GL3_GFXLIB=GLFW \
  -DREVC_AUDIO=OAL -DREVC_WITH_OPUS=OFF -DREVC_WITH_LIBSNDFILE=OFF
cmake --build reVC-source-host/build-host --parallel
```

Current Homebrew metadata confirms all four formulas exist, are neither disabled nor deprecated, and advertise macOS ARM64 bottles: [cmake](https://formulae.brew.sh/api/formula/cmake.json), [glfw](https://formulae.brew.sh/api/formula/glfw.json), [openal-soft](https://formulae.brew.sh/api/formula/openal-soft.json), [mpg123](https://formulae.brew.sh/api/formula/mpg123.json). This proves a current dependency path, not a pinned toolchain or successful link on this machine. Use the actual installed versions in the build manifest.

Do not use old CI or README artifact links as build-success evidence. The repository currently returned no releases, and the inspected five most recent Actions records were awaiting action on unrelated branches. Its [Conan workflow](https://github.com/mrxenginner/reVC/blob/a26fff4af555a8a425ac9f17d1dd718d00d1f942/.github/workflows/build-cmake-conan.yml) still specifies Xcode 11.7, Ubuntu 18.04 and older Conan commands. The proposed route is native CMake using readable pinned sources and current local dependencies, independently verified by a new build.

The source still starts with shared model collision geometry: [`CEntity::GetColModel`](https://github.com/mrxenginner/reVC/blob/a26fff4af555a8a425ac9f17d1dd718d00d1f942/src/entities/Entity.h) returns the model-info COL. A per-instance source bridge and its query tests remain necessary.

### Alternative: Cai1Hsu/re3 miami plus the Apple Silicon build kit

The actual reVC source host is [`Cai1Hsu/re3` at `e19f40616349938de2ae02912a17813cc86ced15`](https://github.com/Cai1Hsu/re3/tree/e19f40616349938de2ae02912a17813cc86ced15), the observed `miami` tip. Its [complete tree](https://api.github.com/repos/Cai1Hsu/re3/git/trees/e19f40616349938de2ae02912a17813cc86ced15?recursive=1) contains the required World, Entity, Physical, Collision and Plane engine code; its [CMake root](https://github.com/Cai1Hsu/re3/blob/e19f40616349938de2ae02912a17813cc86ced15/CMakeLists.txt) selects reVC.

[`aayanrahman/re3-macos-arm64` at `2918b73ecbf5fc6b9a170aa1ac47846efd129208`](https://github.com/aayanrahman/re3-macos-arm64/tree/2918b73ecbf5fc6b9a170aa1ac47846efd129208) supplies source patches and a [build script](https://github.com/aayanrahman/re3-macos-arm64/blob/2918b73ecbf5fc6b9a170aa1ac47846efd129208/scripts/build.sh) for that host. The script selects `miami` for reVC, patches Apple Silicon Homebrew paths, C-versus-C++ language flags, GLFW defines and Retina/window handling, generates required files and invokes `release_macosx-arm64-librw_gl3_glfw-oal`. Its [README](https://github.com/aayanrahman/re3-macos-arm64/blob/2918b73ecbf5fc6b9a170aa1ac47846efd129208/README.md) documents the procedure.

The kit pins only a short librw hash; the exact readable [aap/librw revision](https://github.com/aap/librw/commit/bb7fb685316c973e5cf1c1763299d4eef0e1ec4e) is `bb7fb685316c973e5cf1c1763299d4eef0e1ec4e`. The script leaves the engine branch floating and writes to fixed home-directory locations, so it is not a complete immutable recipe as published. To use it reproducibly, pin the engine and kit revisions above, use an isolated checkout and retain the patch/generated-file provenance. No patch-application or compilation success is claimed here.

Its additional documented dependencies remain available with ARM64 bottles: [premake](https://formulae.brew.sh/api/formula/premake.json), [libsndfile](https://formulae.brew.sh/api/formula/libsndfile.json) and [glew](https://formulae.brew.sh/api/formula/glew.json), alongside GLFW/OpenAL/mpg123. Prefer the first candidate because its native macOS fixes and app generation already reside in the engine's pinned build files.

### Alternative with Metal: reconstructible revc-metal source host

[`mindingulove/revc-metal` at `27d68bb3f127d316ae9afe2590644326e36349f8`](https://github.com/mindingulove/revc-metal/tree/27d68bb3f127d316ae9afe2590644326e36349f8) publishes a build kit with engine/library patches, rather than a complete engine checkout. Its [build script](https://github.com/mindingulove/revc-metal/blob/27d68bb3f127d316ae9afe2590644326e36349f8/build.sh) and [installation guide](https://github.com/mindingulove/revc-metal/blob/27d68bb3f127d316ae9afe2590644326e36349f8/docs/INSTALL.md) pin the actual reVC engine to [`hottabxp/re3` `a16fcd8d6a79e433c1c6e73d540f1bbe27e14164`](https://github.com/hottabxp/re3/tree/a16fcd8d6a79e433c1c6e73d540f1bbe27e14164) and librw to [`aap/librw` `18532c2e13efbc1aa43f0b00b4459831f9414de0`](https://github.com/aap/librw/commit/18532c2e13efbc1aa43f0b00b4459831f9414de0). Both exact upstream revisions were readable. The [engine tree](https://api.github.com/repos/hottabxp/re3/git/trees/a16fcd8d6a79e433c1c6e73d540f1bbe27e14164?recursive=1) contains the native query/contact source files, and its CMake target is reVC.

The guide explicitly targets Apple Silicon and reports M1 renderer builds/GPU fixtures; those are the author's reported results, not results reproduced here. Additional [glslang](https://formulae.brew.sh/api/formula/glslang.json) and [spirv-cross](https://formulae.brew.sh/api/formula/spirv-cross.json) formulas are available with ARM64 bottles. The patch path includes a native Metal renderer and considerable mod/rendering behavior. The project's own [README](https://github.com/mindingulove/revc-metal/blob/27d68bb3f127d316ae9afe2590644326e36349f8/README.md) and guide retain open gameplay/performance and framework-abort limitations. This is an alternative when native Metal is a requirement, with a substantially larger change surface than the first query-authority slice. There is no evidence tying it to macVC 5217 source or its binary identity.

Other inspected hits do not improve the immediate decision: [hammerill/reVC-mac-fpv](https://github.com/hammerill/reVC-mac-fpv) and [twalichiewicz/revc-modernized](https://github.com/twalichiewicz/revc-modernized) are binary-plugin source trees; [AltronMaxX/reVC](https://github.com/AltronMaxX/reVC) contains engine code but currently documents Windows/Linux builds rather than a native macOS ARM64 route. Their existence is not matching-source evidence.

## Access limits and the next acceptance gate

Connected GitHub tools handled repository/source inspection and searches. Their generic fetch rejected some otherwise public endpoint classes (tags/workflow collections and wiki URLs) with HTTP 400 `INVALID_ARGUMENT`. Public unauthenticated HTTPS reads using system `curl` supplied those reads, owner/profile/gist/fork enumeration, the raw wiki, formula metadata and binary-archive listing; no access controls were bypassed. A first Python HTTPS attempt failed certificate-chain verification locally; the successful system `curl` requests retained certificate verification. The empty `maclcs` contents response was HTTP 404. These access outcomes describe the methods' limits, not evidence that unrelated private source does not exist.

This is a bounded public-source investigation. It does not inspect private repositories, deleted/unreachable historical objects, undocumented maintainer storage or the user's other disks/accounts. There is no claim that matching source cannot exist. No public matching-source delivery or source-built matching bridge was located through the inspected paths.

The concrete choices are:

1. **Require matching macVC behavior:** obtain a complete source/build delivery for the exact audited executable, or a newer reproducible macVC host with an engine-implemented bridge. The current public download path cannot supply this. No contact or source request has been sent.
2. **Proceed on a distinct source host:** build the pinned mrxenginner candidate in a separately named location, record all build inputs and the resulting binary identity, and establish its baseline before adding the bridge. This is the recommended source route for the bounded proof; preserve the installed production app and do not apply its fixed-address plugin adapter to this host.
3. **Require native Metal in the source host:** evaluate the reconstructible Metal kit separately, retaining its exact base/patch inputs and larger compatibility scope.

After a real host build, the next proof must show one publication of actual damaged-wing geometry reaching native physical contacts, ordinary LOS, LOS-clear and vertical consumers, while a second same-model aircraft remains intact. Confirm bounds/sector membership and COL/cache/resource lifetime as part of the publication. Detached-wing participation, render geometry, motion ownership and lifecycle acceptance remain separate required contracts from the earlier audit. A source tree, a successful build, or a small synthetic resolver test alone does not prove those live-game contracts.
